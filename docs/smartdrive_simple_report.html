1.1 Distance & Kinematics Calculation Engine

File: backend/src/simulation/DistanceCalculator.ts
Computes Euclidean distance, longitudinal distance, lateral offset, closing velocity, and dynamic Time-to-Collision (TTC).

DistanceCalculator.ts (Authoritative Calculation Module)
export class DistanceCalculator {
  public static calculate(
    ourX: number,
    ourY: number,
    ourSpeed: number,
    targetX: number,
    targetY: number,
    targetSpeed: number,
    targetLane: number,
    ourLane: number = 3
  ): DistanceMetrics {
    const dx = targetX - ourX;
    const dy = targetY - ourY;

    // True Euclidean distance in 3D ground plane
    const euclidean = Math.sqrt(dx * dx + dy * dy);

    // Longitudinal separation along highway axis
    const longitudinal = Math.abs(dy);

    // Lateral separation perpendicular to highway axis
    const lateral = Math.abs(dx);

    // Relative longitudinal velocity: positive when target moves faster downroad
    const relativeVelocity = targetSpeed - ourSpeed;

    // Time-To-Collision (TTC) calculation with directional checks
    const ttc = this.calculateTTC(dy, relativeVelocity);

    return {
      euclidean: parseFloat(euclidean.toFixed(2)),
      longitudinal: parseFloat(longitudinal.toFixed(2)),
      lateral: parseFloat(lateral.toFixed(2)),
      relativeVelocity: parseFloat(relativeVelocity.toFixed(2)),
      ttc: ttc !== null ? parseFloat(ttc.toFixed(2)) : null,
    };
  }

  private static calculateTTC(dy: number, relativeVelocity: number): number | null {
    if (dy > 0) {
      // Target is ahead: distance decreases if ourSpeed > targetSpeed (relativeVelocity < 0)
      const closingSpeed = -relativeVelocity;
      if (closingSpeed > 0.2) {
        const ttc = dy / closingSpeed;
        return ttc >= 0 && ttc <= 30 ? ttc : null;
      }
    } else if (dy < 0) {
      // Target is behind: distance decreases if targetSpeed > ourSpeed (relativeVelocity > 0)
      const closingSpeed = relativeVelocity;
      if (closingSpeed > 0.2) {
        const ttc = Math.abs(dy) / closingSpeed;
        return ttc >= 0 && ttc <= 30 ? ttc : null;
      }
    }
    return null;
  }
}

1.2 Dual-Corridor Safety State Machine & Hysteresis Engine

File: backend/src/simulation/WarningEngine.ts
Applies lane-specific safety thresholds (10.0m for same-lane front/rear vehicles, 1.0m for side-lane passing vehicles) with a 0.3m hysteresis deadband to prevent oscillation.

WarningEngine.ts (Dual-Corridor Safety State Machine)
export class WarningEngine {
  private previousStates: Map<string, SafetyStatus> = new Map();

  public evaluateStatus(
    distance: number,
    ttc: number | null,
    previousState: SafetyStatus,
    settings: SimulationSettings,
    isSameLane: boolean = true
  ): SafetyStatus {
    const H = 0.3; // 30cm hysteresis deadband

    if (isSameLane) {
      // Front & Rear Corridor Thresholds (Same Lane)
      const dangerThresh = settings.dangerDistanceThreshold;   // 5.0m
      const cautionThresh = settings.cautionDistanceThreshold; // 10.0m

      if (previousState === 'DANGER') {
        if (distance > dangerThresh + H) {
          return distance <= cautionThresh ? 'CAUTION' : 'SAFE';
        }
        return 'DANGER';
      }

      if (previousState === 'CAUTION') {
        if (distance <= dangerThresh) return 'DANGER';
        if (distance > cautionThresh + H) return 'SAFE';
        return 'CAUTION';
      }

      // Current State: SAFE
      if (distance <= dangerThresh || (ttc !== null && ttc < 1.5)) return 'DANGER';
      if (distance <= cautionThresh || (ttc !== null && ttc < 3.0)) return 'CAUTION';
      return 'SAFE';
    } else {
      // Side Lane Corridor Thresholds (Passing & Overtaking Traffic)
      const sideDangerThresh = settings.sideDangerDistanceThreshold ?? 0.5;   // 0.5m
      const sideCautionThresh = settings.sideCautionDistanceThreshold ?? 1.0; // 1.0m

      if (previousState === 'DANGER') {
        if (distance > sideDangerThresh + H) {
          return distance <= sideCautionThresh ? 'CAUTION' : 'SAFE';
        }
        return 'DANGER';
      }

      if (previousState === 'CAUTION') {
        if (distance <= sideDangerThresh) return 'DANGER';
        if (distance > sideCautionThresh + H) return 'SAFE';
        return 'CAUTION';
      }

      // Current State: SAFE
      if (distance <= sideDangerThresh) return 'DANGER';
      if (distance <= sideCautionThresh) return 'CAUTION';
      return 'SAFE';
    }
  }

  public processVehicle(
    vehicle: Vehicle,
    settings: SimulationSettings,
    ourLane: number = 3
  ): { status: SafetyStatus; event: WarningEvent | null } {
    const prevState = this.previousStates.get(vehicle.id) ?? 'SAFE';
    const isSameLane = vehicle.lane === ourLane;
    const newStatus = this.evaluateStatus(vehicle.distance, vehicle.ttc, prevState, settings, isSameLane);

    let event: WarningEvent | null = null;
    if (newStatus !== prevState) {
      if (newStatus === 'CAUTION' || newStatus === 'DANGER') {
        event = {
          id: `${vehicle.id}-${Date.now()}`,
          vehicleId: vehicle.id,
          vehicleName: vehicle.name,
          timestamp: Date.now(),
          type: newStatus,
          distance: vehicle.distance,
          ttc: vehicle.ttc,
          message: `${vehicle.name} entered ${newStatus} zone (${vehicle.distance.toFixed(1)}m, Lane ${vehicle.lane})`,
        };
      }
      this.previousStates.set(vehicle.id, newStatus);
    }

    return { status: newStatus, event };
  }
}

1.3 RTOS Cyclic Executive & Simulation Loop

File: backend/src/simulation/SimulationEngine.ts
The simulation loop operates deterministically every 100ms. It updates vehicle kinematics, calculates distances, evaluates safety thresholds, updates the bounded queue, and broadcasts updates.

SimulationEngine.ts (Periodic Cyclic Executive Tick)
public tick(): void {
  if (this.isPaused) return;

  const dt = this.settings.tickRateMs / 1000.0;
  this.tickCount++;

  // Step 1: Update reference vehicle acceleration, braking, and lane alignment
  this.updateOurVehicle(dt);

  // Step 2: Update all 9 surrounding vehicles and calculate authoritative metrics
  for (const [id, vehicle] of this.vehicles.entries()) {
    this.updateVehicleKinematics(vehicle, dt);

    const metrics = DistanceCalculator.calculate(
      this.ourVehicle.x,
      this.ourVehicle.y,
      this.ourVehicle.speed,
      vehicle.x,
      vehicle.y,
      vehicle.speed,
      vehicle.lane,
      this.ourVehicle.lane
    );

    vehicle.distance = metrics.euclidean;
    vehicle.longitudinalDistance = metrics.longitudinal;
    vehicle.lateralDistance = metrics.lateral;
    vehicle.relativeVelocity = metrics.relativeVelocity;
    vehicle.ttc = metrics.ttc;

    const { status, event } = this.warningEngine.processVehicle(
      vehicle,
      this.settings,
      this.ourVehicle.lane
    );
    vehicle.status = status;

    if (event) {
      this.eventQueue.enqueue(event);
      this.database.saveEvent(event);
    }
  }

  // Step 3: Broadcast complete authoritative state snapshot via WebSocket
  this.broadcastState();
}

1.4 Bounded Event Queue Subsystem

File: backend/src/simulation/BoundedEventQueue.ts
Implements a strict O(1) bounded memory circular buffer (capacity N = 100). Employs FIFO eviction when full to guarantee zero buffer overflow or memory leaks under high warning frequency.

BoundedEventQueue.ts (OS Producer-Consumer Pattern)
export class BoundedEventQueue {
  private queue: WarningEvent[] = [];
  private readonly capacity: number;
  private droppedCount: number = 0;
  private highWaterMark: number = 0;

  constructor(capacity: number = 100) {
    this.capacity = capacity;
  }

  // Producer operation: Drops oldest event if full (FIFO replacement policy)
  public enqueue(event: WarningEvent): boolean {
    if (this.queue.length >= this.capacity) {
      this.queue.shift(); // Drop oldest
      this.droppedCount++;
    }

    this.queue.push(event);

    if (this.queue.length > this.highWaterMark) {
      this.highWaterMark = this.queue.length;
    }

    return true;
  }

  public dequeue(): WarningEvent | undefined {
    return this.queue.shift();
  }

  public getMetrics(): OSMetricQueueInfo {
    return {
      size: this.queue.length,
      capacity: this.capacity,
      droppedCount: this.droppedCount,
      highWaterMark: this.highWaterMark,
    };
  }
}

1.5 Dynamic 3D Camera Chase Controller

File: frontend/src/components/3d/CameraManager.tsx
Locks the 3rd-person chase camera directly behind the vehicle's active lane coordinate ($x = ( ext{lane} - 3) imes 3.6 ext{m}$), eliminating lateral visual parallax distortion.

CameraManager.tsx (3D Camera Lane Alignment)
export const CameraManager: React.FC<Props> = ({ viewMode, ourVehicle }) => {
  const { camera } = useThree();
  const currentLookAt = useRef(new THREE.Vector3(0, 1.5, -25));

  useFrame((_, delta) => {
    let targetPos = new THREE.Vector3(ourVehicle.x, 7.0, 14.0);
    let targetLook = new THREE.Vector3(ourVehicle.x, 1.4, -26.0);

    // Frame-rate independent exponential damping
    camera.position.x = THREE.MathUtils.damp(camera.position.x, targetPos.x, 6, delta);
    camera.position.y = THREE.MathUtils.damp(camera.position.y, targetPos.y, 6, delta);
    camera.position.z = THREE.MathUtils.damp(camera.position.z, targetPos.z, 6, delta);

    currentLookAt.current.x = THREE.MathUtils.damp(currentLookAt.current.x, targetLook.x, 8, delta);
    currentLookAt.current.y = THREE.MathUtils.damp(currentLookAt.current.y, targetLook.y, 8, delta);
    currentLookAt.current.z = THREE.MathUtils.damp(currentLookAt.current.z, targetLook.z, 8, delta);

    camera.lookAt(currentLookAt.current);
  });

  return null;
};

2.1 Full-Stack Technical Stack & Component Breakdown

  • Authoritative Backend: Node.js 24 with TypeScript, Express REST API, and native Socket.IO engine. Runs on port 4000.
  • Frontend 3D Visualizer: React 18, Vite, Three.js, React Three Fiber (R3F), and Drei helpers. Runs on port 5180.
  • Storage Subsystem: Native Node.js SQLite (node:sqlite) running in Write-Ahead Logging (WAL) mode for non-blocking asynchronous event writes.
  • Testing Infrastructure: Vitest for isolated unit testing, Supertest for HTTP REST endpoint assertions, and Socket.IO client integration test harness.

2.2 Step-by-Step Data Flow Pipeline

  1. Cyclic Clock Interrupt ($T = 100 ext{ ms}$, $10 ext{ Hz}$): The periodic executive triggers the master simulation tick.
  2. Kinematic State Integration: Our reference vehicle and 9 surrounding vehicles update velocities and coordinates: $$\Delta y = (v_{ ext{target}} - v_{ ext{our}}) \cdot \Delta t$$
  3. Spatial Metric Extraction: DistanceCalculator executes mathematical calculations for true Euclidean distance $d = \sqrt{\Delta x^2 + \Delta y^2}$, longitudinal separation $|\Delta y|$, and Time-to-Collision (TTC).
  4. Dual-Corridor Decision Logic: Evaluates whether a vehicle is in the same lane ($|\Delta x| < 1.8 ext{m}$) or a different lane. Same-lane vehicles use the $10.0 ext{m}$ warning corridor; side-lane vehicles use the $1.0 ext{m}$ passing warning corridor.
  5. Event Generation & Buffering: If a state transition occurs (SAFE ↔ CAUTION ↔ DANGER), an immutable WarningEvent is pushed into the bounded circular queue ($N = 100$) and committed to SQLite.
  6. WebSocket Broadcast & 3D Rendering (60 FPS): Full state snapshots are emitted to all connected browser clients. React Three Fiber updates vehicle meshes, scrolling asphalt lane markings, and colored laser detection vectors.

2.3 Coordinate System & Lane Alignment

The roadway consists of 5 standard highway lanes of width $W = 3.6 ext{ meters}$. Lateral positions ($x$) are centered symmetrically around $x = 0.0 ext{m}$ (Lane 3):

  • Lane 1 (Far Left): $x = -7.2 ext{ meters}$
  • Lane 2 (Left Lane): $x = -3.6 ext{ meters}$
  • Lane 3 (Center Lane - Reference Car): $x = 0.0 ext{ meters}$
  • Lane 4 (Right Lane): $x = +3.6 ext{ meters}$
  • Lane 5 (Far Right): $x = +7.2 ext{ meters}$

The lateral steering formula is given by: $x = ( ext{lane} - 3) imes 3.6 ext{m}$.

3.4 Operating Systems Principles Explored

  • Authoritative ECU vs. Untrusted Display Layer: Real-time safety systems dictate that safety decisions occur inside a deterministic kernel. The browser frontend is treated as an untrusted visualizer. Even if client-side rendering drops frames, the backend distance calculations, SQLite persistence, and emergency brake events remain completely unaffected.
  • Cyclic Executive Scheduling: Chosen over preemptive multi-threading to eliminate race conditions and deadlocks. At each 100ms cycle, sensor integration and distance math execute synchronously, guaranteeing identical evaluation across all simulated vehicles.
  • Bounded Buffer with FIFO Eviction: Prevents buffer overflow and out-of-memory errors by maintaining an invariant fixed queue capacity ($N = 100$). When burst events occur, the oldest warnings are dropped while recording dropped-packet metrics.
  • Event Hysteresis & State Transition Debouncing: Prevents rapid warning oscillation ("chattering") when distance hovers near threshold boundaries ($0.3 ext{m}$ deadband applied during state transitions).
  • Single-Writer Principle & Non-Blocking Persistence: The simulation loop acts as the sole writer of the authoritative vehicle state. Event logging to SQLite utilizes Write-Ahead Logging (WAL) mode, guaranteeing zero frame stuttering during disk I/O.
